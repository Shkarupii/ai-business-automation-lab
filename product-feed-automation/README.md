# Product Feed Automation

Практичний демонстраційний інструмент для автоматизації обробки товарного фіда постачальника за допомогою Python, AI та Vibe Coding.

> ⚠️ Проєкт використовує **лише синтетичні демонстраційні дані**. Реальні дані компаній, постачальників або товарних каталогів не публікуються.

---

## Бізнес-задача

У реальному e-commerce постачальники передають прайси та товарні фіди у різних структурах. Перед імпортом на сайт, у CRM або ERP дані потрібно очистити, перевірити та привести до єдиного формату.

```text
CSV постачальника
        ↓
читання та нормалізація
        ↓
перевірка SKU, ціни, залишку, категорії та статусу
        ↓
коректні товари + журнал помилок
        ↓
стандартизований інтеграційний фід
```

Інструмент показує, як за допомогою AI та Vibe Coding швидко створити зрозумілий робочий прототип для такої задачі.

---

## Що робить інструмент

Скрипт `process_feed.py` автоматично:

- читає CSV постачальника з українськими назвами полів;
- очищує пробіли та нормалізує SKU;
- перевіряє SKU на наявність і дублікати;
- зіставляє категорії з довідником;
- перевіряє та округлює ціну;
- перевіряє залишок;
- нормалізує статус товару;
- відокремлює коректні рядки від помилкових;
- створює стандартизований фід, журнал помилок і підсумковий звіт.

Для v1 підтримується тільки валюта `UAH`.

## Вхідні дані

Демонстраційний файл:

`examples/demo-supplier-feed.csv`

| Поле | Призначення |
|---|---|
| `артикул` | SKU постачальника |
| `назва` | Назва товару |
| `категорія` | Категорія у фіді постачальника |
| `ціна` | Поточна ціна |
| `валюта` | Код валюти; для v1 — тільки `UAH` |
| `залишок` | Доступна кількість |
| `статус` | Статус у системі постачальника |
| `штрихкод` | Штрихкод товару |

Вхідний CSV навмисно залишено українською мовою, щоб імітувати звичайний локальний прайс або фід постачальника.

Файл містить коректні товари та спеціальні тестові помилки: пропуски, дублікати, неправильні числа, невідомі категорії, некоректні статуси й іншу валюту.

## Стандартизований вихідний формат

Коректні товари записуються до:

`output/standardized-product-feed.csv`

| Поле | Призначення |
|---|---|
| `sku` | Нормалізований SKU |
| `product_name` | Очищена назва товару |
| `category` | Стандартизована категорія |
| `price_uah` | Ціна у гривні з двома десятковими знаками |
| `stock_qty` | Цілий залишок |
| `availability` | `in_stock` або `out_of_stock` |
| `status` | `active`, `inactive` або `out_of_stock` |
| `barcode` | Штрихкод товару |

Англомовні технічні поля використані як універсальний інтеграційний формат для подальшої передачі даних на сайт, у CRM, ERP або API.

## Правила валідації

| Перевірка | Результат |
|---|---|
| Відсутній SKU | Рядок відхиляється |
| Дубль SKU | Після нормалізації відхиляються всі конфліктні рядки |
| Порожня ціна | Рядок відхиляється |
| Нульова ціна | Рядок відхиляється |
| Від'ємна ціна | Рядок відхиляється |
| Некоректний формат ціни | Рядок відхиляється |
| Порожній залишок | Рядок відхиляється |
| Від'ємний залишок | Рядок відхиляється |
| Нульовий залишок | Дозволено; товар отримує `out_of_stock` |
| Невідома категорія | Рядок відхиляється |
| Некоректний статус | Рядок відхиляється |
| Порожня назва | Рядок відхиляється |
| Валюта не UAH | Рядок відхиляється |

### Нормалізація SKU

Пробіли на початку та в кінці прибираються, а літери переводяться у верхній регістр. Тому `PF-007`, `pf-007` і ` PF-007 ` вважаються одним SKU.

Якщо знайдено дубль, жоден із конфліктних рядків не потрапляє до стандартизованого фіда. Кожен конфліктний рядок окремо записується до `feed-errors.csv`.

### Нормалізація статусів

| Значення постачальника | Стандартний статус |
|---|---|
| `активний`, `в продажу`, `active` | `active` |
| `неактивний`, `знятий`, `inactive` | `inactive` |
| `немає`, `закінчився`, `out_of_stock` | `out_of_stock` |

За нульового залишку статус автоматично стає `out_of_stock`.

## Результати

Після запуску створюються:

### `standardized-product-feed.csv`

Тільки коректні товари, готові для наступного етапу інтеграції.

### `feed-errors.csv`

Кожна помилка містить:

- номер рядка вихідного CSV;
- нормалізований SKU;
- технічний код помилки;
- проблемне поле та значення;
- зрозуміле пояснення українською мовою.

Один товар може мати декілька записів, якщо в одному рядку знайдено кілька помилок.

### `processing-summary.md`

Короткий бізнес-звіт із кількістю вхідних, успішних і відхилених рядків, quality rate, статистикою дублів, TOP-5 причин помилок та рекомендаціями.

➡️ [Переглянути підсумок обробки](output/processing-summary.md)

## Як запустити

Перейти до папки проєкту:

```bash
cd product-feed-automation
```

Запустити:

```bash
python process_feed.py
```

Зовнішні Python-залежності не потрібні.

## Roadmap

### v1 — поточна версія

- синтетичний CSV одного постачальника;
- нормалізація й валідація ключових полів;
- стандартизований CSV;
- журнал помилок;
- підсумковий Markdown-звіт.

### v1.1 — зручність і контроль

- параметри командного рядка для вибору файлів;
- конфігурація статусів;
- окремі попередження та критичні помилки;
- автоматичні тести;
- розширена статистика якості фіда.

### v2 — інтеграційний рівень

- підтримка Excel, XML і JSON;
- декілька форматів постачальників;
- конвертація валют і правила націнки;
- порівняння з попереднім фідом;
- контроль різких змін ціни та залишку;
- експорт для конкретного сайту, CRM, ERP або API;
- опційне AI-зіставлення невідомих категорій.
